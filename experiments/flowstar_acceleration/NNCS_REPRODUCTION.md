# Xiangru NNCS qualification experiments

These files record **plant runtime strict-mode** attempts; final plant qualification is pending the endpoint repair described below. The native-f64 auto_LiRPA CROWN affine/bias computation has no proved outward roundoff accounting, so no result here is a strict end-to-end NNCS certificate. `VERIFIED`, `UNKNOWN`, or `FALSIFIED` printed by the source driver are recorded protocol messages subject to that qualification. In particular, a first-period target check is not a full-horizon property result.

The original benchmark boxes, split counts, controller, plant step, Taylor order, cutoff and horizon are retained in `configs_nncs/*_full.yaml`. `*_period1.yaml` explicitly limits the scope to one original control period; it does not replace a larger batch by B=1. The original QUAD contract remains invalid because h=.01 exceeds its .005 control period. `quad_submit_native_*` is a separate, source-backed extra case: B=1024, n=16, h=.005, order 2, 50 control periods of .1, T=5, remainder ±.1, cutoff 1e-6 and SR capacity 1000. Airplane is retained as a resource/layout qualification blocker rather than being silently reduced.

These are reproducible experiment scripts, with absolute paths to the recorded source checkout and controller models. They expect the archived Xiangru checkout at commit `1c16d4ef2cb91cc94b1c784f7383e1eba135d8d3` and an explicitly selected engine checkout. The campaign used an isolated `nncs_env` over Python 3.11, torch 2.5.1+cu121, ONNX 1.22.0, onnx2pytorch and the recorded auto_LiRPA 0.7 checkout. It did not modify the original Python environment or replace torch/CUDA. Installation manifests and all run-specific metadata are retained with the experiment evidence.

## Entry points

- `nncs_screen.py`: baseline archive qualification and one-period screening.
- `nncs_candidate.py`, `nncs_full_campaign.py`: the frozen 9d83162 candidate and complete original-config campaign.
- `nncs_acc_adapter.py`: explicit source-derived ACC features, constructing Taylor-model differences before range evaluation and reusing those same features for controller injection; adapter roundoff is tracked separately from unqualified CROWN arithmetic.
- `nncs_tora_diagnostic.py`, `nncs_tora_replay.py`: captured CROWN call/layout diagnosis; the source explicitly requires `conv_mode=matrix` for homogeneous TORA.
- `nncs_cartpole_ledger.py`: initial-self-map versus bad-domain rejection evidence.
- `nncs_nav_memory.py`, `nncs_nav_cache_budget.py`: default-pool versus graph-pool diagnosis, then success-step inactive-cache cleanup above 2 GiB with cost included.
- `nncs_quad_candidate.py`: five-extension QUAD run pinned to engine 5d1bac0.
- `nncs_quad_memory.py`: explicit `--expected-engine-sha`, strict CUDA point-history chunks, owned graph outputs, largest-buffer-first growth, an allocator cap of 9 GiB, and recorded inactive-cache cleanup at actual SR capacity growth. `--reserve-sr-full` explicitly reserves capacity 1000 while qlen/jlen are zero for a known full horizon; it does not alter queue capacity or reset rules. The resource wrapper retains the observed 11.5 GiB RSS/GPU guard and 600-second full-run timeout. The initial 5d run exceeded the 12 GiB budget briefly during the sampling interval; that failure is retained rather than called a successful resource-bound run.
- `sr_sum_kernels.py`: the validated standalone J-history prototype. The engine integration has identical CPP/CUDA arithmetic, with the import and extension name adjusted; the production integration is in the engine commits, not a runtime monkeypatch from this file.

The native full QUAD runner uses `FLOWSTAR_COMPOSITION=horner`, `FLOWSTAR_GLUE=graph`, `FLOWSTAR_SUPPORT_POLICY=measured`, one torch thread and one CPU core. Preload interval, tape, validation, SR Phi and SR J-history extensions before solve; report first compilation separately. Every recorded run includes the engine SHA, source/config/runner hashes, extension identities, actual extension calls, accepted lanes, per-step width data, full endpoint/tube gzip trace, graph counters and timing. Observer and gzip costs remain in the actual process total. Successful-step cleanup costs remain in plant/driver/process totals. Upfront reservation and its cleanup are reported as SR initialization and included in child/process wall time; the original driver loop timer starts after this initialization, so it is not presented as including that phase.

Do not confuse unavailable global test collection dependencies with failed arithmetic assertions: the small self-contained SR suites ran with `--noconftest`, and the standalone ownership script invokes the original determinism fixture directly. That script preserves the lifecycle assertions while selecting the frozen truncated-validation policy, since the optional deferred policy is absent from the QUAD worktree.

Large traces remain under `/srv/local/shengenli/flowstar_acceleration_20260921T153643Z/runs/`; the small evidence archives contain trace hashes, resource logs, source snapshots, validation scripts and manifests. Local evidence is under `results/flowstar_acceleration_20260921/nncs/`. Failed or guard-terminated attempts are separate directories. A truncated gzip is audited using complete flushed records without rewriting the original file.

A later Airplane integration audit identified unresolved FULL/spatial support-ID mixing in the public endpoint helper. These frozen NNCS runs are historical observations pending correction and rerun; no final strict qualification follows from them. The standalone directed-arithmetic oracles remain separately documented.
