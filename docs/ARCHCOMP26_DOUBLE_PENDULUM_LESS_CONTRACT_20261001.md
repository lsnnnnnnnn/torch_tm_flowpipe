## Common mathematical and control contract

| Field | Value and evidence |
| --- | --- |
| System | Continuous four-state plant with sampled, held neural control. Physical state order is `[theta1, theta2, theta1_dot, theta2_dot]`, as in report page 94 and the official MATLAB source. A clock and two held controls in an implementation are auxiliary variables. |
| Plant parameters | `m=0.5`, `L=0.5`, `c=0`, `g=1`, from report page 93 and the official MATLAB source comment. Use the full four derivatives in `dynamics_dp.m`; no disturbance term is present there. |
| Controller | The official `controller_double_pendulum_less_robust.onnx` specifically paired with Specification 1 by report page 95 and `Specifications.txt`. The graph itself has one float32 input of shape `[N,4]`, one float32 output of shape `[N,2]`, three `MatMul` and three `Add` nodes, and two `Relu` nodes. No graph preprocessing or scaling node was found. Historical CROWN `crown_less_robust.py:35–51` passes all four states in order and uses output scale 1 and offset 0; historical `double_pendulum_less_robust.cpp:34–48,171–185` maps output 1 to `T1` and output 2 to `T2`. |
| Initial set | Full physical box `[1.0,1.3]^4`, from report page 94 and `Specifications.txt`. |
| Schedule | Evaluate the controller at each interval start, then hold `(T1,T2)` during the following `0.05 s` plant step. Run 20 intervals: `t=0` through `t=1.0 s`, with controller evaluations at `t=0,0.05,...,0.95`. This follows the official time step and the saved CROWN loop's NN-before-plant order (`double_pendulum_less_robust.cpp:129–207`). |
| Property | Specification 1: for **all** continuous time `t∈[0,1]`, each of the four physical states lies in `[-1.7,2]`. This is a whole-tube property, not merely a final-state target (report page 94). The saved CROWN source passes these eight inequalities to each 0.05 s `reach` call. |
| Discrete counterpart | The report also defines `k=0,...,20` using forward Euler at `Δt=0.05`. It is a different model variant; a continuous run must not be relabeled as its discrete result. The 2026 top-level README lists only the two robustness rows, so record model kind explicitly. |

The official MATLAB source gives `theta1'=theta1_dot`, `theta2'=theta2_dot`, and explicit formulas for the two accelerations. The saved YAML's first two derivatives use the names `u1,u2` for the two angular velocities; after this variable renaming, the official source and saved YAML's four derivative expressions agree character-for-character after whitespace normalization. This check compared expression text; it did not infer equality from filenames. The old CROWN `.cpp` contains those same expressions.

## Partition and numerical method boundary

The report and official instance file specify the **full initial box**; they do not require a numerical partition. The saved author code splits the four physical coordinates `5×5×3×3`, giving 225 subboxes, and the saved candidate boxes file contains all 225 Cartesian combinations covering `[1,1.3]^4`. Using those 225 boxes for the new shared experiment is an explicit comparison choice. A one-period plumbing smoke should still include every box and must be labeled incomplete; a complete row requires all 20 controller periods and all boxes or a visible failure/early stop for each method.

Historical native settings are fixed ODE step `0.01`, Taylor order `4`, cutoff `1e-6`, remainder estimate `[-0.01,0.01]`, and symbolic-remainder queue `1000` (`double_pendulum_less_robust.cpp:54–60` and saved YAML). They are **method settings**, not a claim that the official benchmark prescribes these values to every algorithm. Freeze each method's actual settings and timing boundary in its result record.

The saved CROWN Python selects a controller under its `ARCH-COMP2024` tree. A direct byte comparison of the official public 2026 ONNX above with the public [`verivital/ARCH-COMP2024` file at commit `f1a113120cb9145474d68a87244c3f11d8e5893c`](https://github.com/verivital/ARCH-COMP2024/blob/f1a113120cb9145474d68a87244c3f11d8e5893c/benchmarks/Double_Pendulum/controller_double_pendulum_less_robust.onnx) found the files identical. On the server, the corresponding copies under `CROWN-Reach`, `CROWN-Reach-GPU`, and `CROWN-Reach_Development` were also compared directly byte-for-byte with the fixed official 2026 file and found identical. Use the fixed 2026 controller as the named input for new runs. The saved *more-robust* candidate is a separate issue: it names the less-robust controller and uses a singleton corner instead of the full official box, so no result from it can fill the 2026 more-robust row.
