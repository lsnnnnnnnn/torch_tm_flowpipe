当前不采用 Xiangru 的可选 GPU 后端，决定为 `DO_NOT_ADOPT_YET__CONFIRMED_CORRECTNESS_DEFECT`。指定分支已成功重新取得，V100 构建和真实 CUDA 执行也已确认；决定来自精确反例。

| 预注册条件 | 本轮结论 | 依据 |
|---|---|---|
| 关键正确性与功能 | 未通过 | 历史矩阵传播和归一化缩放各有一个独立的集合包含性反例；普通、严格模式共用受影响路径 |
| 完整四项宽度 | 未进入接纳评定 | 已知漏包后停止候选长跑；两步诊断不足以评价完整 T20 或 VDP T6.32/T10 |
| B32 严格模式速度 | 未进入接纳评定 | 正确性前提失败；没有完整批量重复或可宣传的吞吐倍率 |
| 自适应步长加历史保存 | 暂不支持 | 固定源码的 Settings 抛出 NotImplementedError；本轮没有关闭历史保存来规避限制 |

原始历史矩阵操作数来自既有证据，其精确第二分量在新源码实际发布的区间之外。归一化反例使用两个独立、常数项为零的仿射 Taylor model `1.1*u_i + [-2^-52,2^-52]`，变量域为 [-1,1]，余项对称且数值处于正常量级，不依赖历史矩阵。两者分别需要处理矩阵连乘与倒数/保留系数缩放的舍入误差，超出本轮一个数值机制修补的预算。候选数值源码保持不变；只读 Flow* 导出接口和 CUDA 编译配置另列在 [CONDITIONAL_PATCH.md](CONDITIONAL_PATCH.md)。

此判断限于这版代码能否作为保证范围的后端。没有断言反例操作数已经出现在冻结长轨迹中；也没有把其他工具的区间当作数学真值。局部测试通过、批量结果逐位一致和哈希完整，都不能抵消已确认的漏包。

| 后续路线 | 具体安排 |
|---|---|
| 保留 | 我们的独立 CPU 参考、现有 VDP 自适应能力、回归测试，以及原生 Flow* 对照 |
| 本轮采用 | 新增的匹配合同、完整对象导出、共同宽度表、精确反例和紧凑证据校验 |
| 暂不接入 | 当前 Xiangru 普通/严格后端；默认 CLI 和我们的数值 src 均不变 |
| 继续暂停 | 从零开发第二套 GPU 引擎、扩大数值修补范围、控制器和第三个动力学系统实验 |
| 下一次重新评估的前提 | 上游或另行授权的工作闭合这两条误差路径，再按同一冻结合同重跑严格全程宽度与 B32 性能；不能仅让一个旧例子通过 |

当前选择不意味着应立即恢复从零写 GPU。现有引擎仍可作为后续候选，但须先有完整的误差包含依据。精确门槛、时域、四项宽度和时间明细见 [REPORT_PLAIN_CHINESE.md](REPORT_PLAIN_CHINESE.md) 及其中链接的原始表。
