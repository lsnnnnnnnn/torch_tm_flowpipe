# 未修改候选的首轮比较

当前不能推荐采用这版严格误差后端。新克隆的普通、严格模式在 CPU 与 CUDA 上都重现了已知历史矩阵漏包；另外，生产缩放函数对一个有限、正常量级的单点输入也遗漏舍入误差。两个问题属于不同运算机制。这里只断言这些局部包含关系失败，不断言相同操作数已经出现在两条冻结轨迹中。

本轮源码固定为 `1c16d4ef2cb91cc94b1c784f7383e1eba135d8d3`，比较合同已在 `a30fade` 提交。候选未改数值代码。两道主试验都只有 x、y 两个真实状态；Brusselator 六阶、步长 0.02、历史容量 1000，VDP 四阶、步长 0.01、历史容量 100。没有切分初始盒子或扩大误差预算。我们的 `validation_eps` 是范围向外扩张，候选的时间起点偏移不是对应参数。

两状态原生 Flow* 已新鲜完成 Brusselator T20 与固定步长 VDP T10。完整求解实测分别为 13.569828379 秒、1.488466354 秒；导出分别为 10.303769863 秒、2.892356023 秒。这是当前机器上的两状态结果，与历史三状态驱动区分。我们的完整 CPU 对照正在产生逐步对象和上下界。

候选只进行两步短诊断，比较 CPU/CUDA、普通/严格以及密集/稀疏调用路线。确认漏包后按目标第 17 节停止受影响的长跑，并且不开展第 20 节以严格正确性通过为前提的批量性能接纳。因此当前没有候选 T20 的完整宽度、普通与严格的全程代价，或 B32 吞吐提升可报告。不能把短诊断的计时外推成它的完整速度。

宽度将分别列出 x/y、终点/整段四项，并用各自完整发布对象的共同范围求值器复算。候选自带 `io.metrics` 直接测内部 `tmvPre`；它不是整个左右映射组合后的同一测量对象，不能直接冒充公平宽度对照。候选短诊断将明确标记不具备严格接纳资格；缺失的全程数据保留为缺失。

CPU 的 145 项相关现有测试通过；CUDA 的 146 项通过，一项因为本轮只暴露设备 0 而跳过跨设备测试。测试通过不覆盖刚才的反例，不构成严格正确性已闭合的结论。

当前采用障碍很具体：历史变换矩阵连乘没有保存其舍入误差，缩放倒数与保留系数的缩放又有独立遗漏。只修前者不能闭合后者。本轮不把一个数值修补扩大成多个机制的重写。保留原生 Flow* 和我们的独立 CPU 参考，GPU 从零开发继续暂停。
