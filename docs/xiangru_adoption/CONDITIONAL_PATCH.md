# 候选修补决定

**NONE：没有改动 Xiangru 数值源码。**

已知历史输入在普通／严格、CPU／CUDA 四条实际路线都漏包。精确第二分量为 `-4503599627370497/38685626227668133590597632`，CUDA 发布区间却约为 `[-2.328306436538698e-10, -2.3283064365386953e-10]`。`flowpipe.advance` 与 `sparse_exec.advance_sparse` 都调用同一条 `symbolic_remainder.propagate`；它的点矩阵乘积没有严格模式分支。

另外，`sparse_exec._g_precond` 对单点 Taylor model `1.1 + [2^-52,2^-52]` 的缩放后表示未包含原精确单点，CPU 与 CUDA 都已通过 Fraction 独立复算确认。这个例子不使用历史矩阵，且所有数值都处于正常量级；不是仅由下溢前提引起的问题。

修历史传播需要包住变换矩阵和连乘误差；修后一个问题需要另外处理缩放倒数、保留系数乘法及其误差归属。它们是两种独立机制，不符合本轮最多一个局部数值修补的约束。不能仅让旧矩阵例子通过就宣称严格路径闭合。因此不建 Xiangru 数值候选 worktree，不复制旧 Huan 修复，也不把有缺陷路径继续用于长程保证范围和性能接纳。

环境适配只有：独立 venv、独立 extension cache、指定现有 GCC 13 给 CUDA 12.6，架构由上游构建函数根据 V100 选择 sm_70；没有更换数值 kernel。原生 Flow* 在新的独立目录增加两个 const 只读导出访问器，数值基准仍为 b85a321；该观察性变更单独固定在本地 722a561。它不是候选数值修补。
