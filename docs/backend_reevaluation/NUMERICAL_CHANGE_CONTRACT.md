# 本轮数值变更合同

**本轮数值源码变更为空。** 我们的 CPU、当前候选、旧修复树和原生 Flow* 均保留原状态。自己的审计分支只增加输入适配器、精确复算、测试和报告。独立第三处端点漏包在复用计划阶段触发停止；没有候选补丁 SHA、补丁包或可选适配器可推荐。

## 已检查的数学对象

历史例读自上一轮原始 JSON。按精确 binary64 操作数计算三个矩阵和两列 J 的组合，最后第二分量为 `-4503599627370497/38685626227668133590597632`。另用相同矩阵及列、在后两个变换中使用选定尺度 binary64(1.1)，检查倒数参与新矩阵形成，未重新随机搜索历史输入。每一阶段逐分量包含必须成立，不使用 tolerance。我们的队列用“当前 J 搭配单位矩阵”而非候选的死首槽，精确映射相同。

归一化例为两个独立 `P_i=binary64(1.1)*u_i`，零常数，`u_i∈[-1,1]`，`I_i=[-2^-52,2^-52]`。原像每个分量恰为 `[-4953959590107547/4503599627370496,4953959590107547/4503599627370496]`。返回像按所选 binary64 尺度 s 与返回 Q、余项精确计算 `s*(Q+I_new)`，比较整个原始像集；不强制内部系数相等，也不把 1.1 当成 11/10。dense 与 sparse 适配器使用各自合法支持布局，含零系数的布局可使向外求范围的尺度略有不同；这不是更换数学输入。

输入适配器只替代被检查映射之前的端点/compose 输出；生产函数本身完成新 Phi、传播或缩放。观察在下一无关阶段前停止，不运行 ODE。归一化观察包括旧版 `_g_precond` 后的 strict 补记与 SR cutoff，避免错把裸 helper 作为旧严格路径。历史检查记录新矩阵点值及旧 strict 区间值。CUDA 保存独立缓存的实际 `.so` 路径与 profiler 的实际 kernel 名；数值只按包含性判断，不按跨设备逐 bit 相等判断。

## 可复用机制与尚未闭合的所有权

旧版的区间倒数记录 `1/s` 的误差，区间乘法记录系数乘倒数的误差，区间 Phi 连乘和 J 像求和继续消费这些区间。保留点矩阵只是原算法代表值。旧版缩放按区间倒数乘原余项，并将 `range(P/s-Q)` 的包络加入归一化后的余项。

如果继续开发，两条链须满足 `I_new ⊇ I/s + range(P/s-Q)`，且新产生的归一化误差以 s 恢复到未缩放当前 J，线性系数乘加误差也进入当前 J；已合并的历史贡献不能再重复追加。现有旧版局部写入 `new_tmv_rem` 不足以证明后续线性历史路径消费了新增量。本轮未实施或认证此闭合。极小非零不得按阈值置零，不能用额外 epsilon、扩大盒子或其他工具并集掩盖漏包。

在这些后续事项之前，端点时间代入已给出独立精确反例，故整条候选开发停止。未检查或未运行的候选前缀、失败任务隔离、完整时域、输出误差只计一次、宽度和计时，均保持未建立。
