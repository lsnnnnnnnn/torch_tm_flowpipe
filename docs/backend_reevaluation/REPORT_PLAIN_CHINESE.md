# 本轮结论：旧修复确实有用，但不能在两处修补范围内接纳当前候选

我们把同样的输入交给三份代码。当前候选的历史传播和归一化漏包都重现了；旧修复版在 CPU 与 V100 的严格 dense、sparse 入口都能包住两例，我们自己的 CPU 对应操作也能包住。这次核对说明旧修复资产值得保留，上一轮没有继续修补的结论也没有被改写。

但在核对真实调用入口时，发现第三处独立遗漏：把时间代入多项式 `-1+100*t`，在机器实际表示的 0.01 处，精确答案约为 `2.08×10^-17`，当前严格代码却给出零，余项也是零。这个小例子尚未使用历史矩阵，也没有归一化。CPU/CUDA 的两种入口都失败，旧修复版都包含。因此按本轮明确的停止规则，**不创建新数值候选，不继续叠加第三个修补，也不进入有缺陷路径的正式长跑。**
