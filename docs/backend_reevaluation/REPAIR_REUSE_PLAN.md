# 旧修复复用结论与停止决定

1. **旧修复是否通过两例？** 是。历史原始矩阵、增加非单位尺度的同源变体，以及零常数仿射归一化，在旧版 CPU/CUDA、dense/sparse 严格入口都通过精确有理数复算。普通模式仍失败。当前候选的对应严格入口失败；我们的 CPU 对应操作通过。这里检查的是两个数学映射，不是完整 strict 模式证明。

2. **当前缺什么？** 源码中同时缺少区间 Phi/scalars 和实际调用处的归一化误差补记，不能只改最后一个 dot。旧版 sparse 的 `_g_precond` 本体也没有保护，但 `advance_sparse` 随后补记误差；本轮观察的是这段完整生产逻辑。旧版线性乘加和归一化新增误差写入 `new_tmv_rem`，而 `append_j` 在其前或只收到原 `j_new`，后续历史所有权还需显式闭合，不能机械复制后就宣布完成。另在同一生产调用函数的入口发现独立的端点时间代入漏包，见下述停止条件。源码只能证明两份快照的差别，不能据此解释维护者的主观选择或变更历史。

3. **若只看两条已知链，需要改哪些函数？** 历史链：`SymbolicRemainder` 的 Phi/scalars 区间保存与 reset、`propagate` 的矩阵更新和历史求和、`flowpipe.advance` / `sparse_exec.advance_sparse` 的新矩阵形成及线性乘加误差当前 J 归属。缩放链：两个 advance 的倒数区间、保留系数误差、余项缩放、物理坐标恢复以及新增误差当前 J 归属；实际 sparse `_g_precond` 之后的保护必须接通。还需处理真零与极小非零、非有限值和未检查的 graph/compile/B 分派。以上均为未实施清单。

4. **本来需要重跑什么？** 原历史反例及旧 `symbolic_phi` 测试；两例在所有实际入口；1/2/3 维、抵消、极小数、0/1/多历史和清空；误差当前状态归属、失败任务隔离、B1/B2/B8；再依合同跑两系统 1–2、20、120 步与完整 T20/T10，逐段四项宽度通过后才测批量性能。本轮已完成两例对称复查、旧四项历史测试、独立障碍复现和证据篡改检查。修复后的其余回归因停止条件未开启。

5. **是否需要替换引擎或重写 CUDA？** 两条已知链的机制有局部复用资产，不需凭空重造；但本候选的严格入口还存在第三条独立遗漏。仅复用两条链不足以满足本轮接纳前提，不能把端点代入修复改名并塞进已授权范围。因此依据目标第 4、8 节，在建立新候选 worktree 前停止，状态为 `REPAIR_REUSE_NOT_LOCAL__NO_ADOPTION`。没有写任何第三方补丁，也没有继续研究通用卷积、控制器或其他系统。

独立障碍：两个分量都取时间多项式 `-1 + 100*t`，余项为零，在 `t=binary64(0.01)` 求终点。当前严格入口在分离中心之前发布的局部表示是零多项式加零余项；精确值为 `3/144115188075855872`。CPU/CUDA、dense/sparse 均漏包；旧版均包含。该操作尚未调用历史、composition 或 normalization，不依赖前两种问题。它是生产入口中的局部反例，不是新增第三个动力系统的长轨迹实验。
