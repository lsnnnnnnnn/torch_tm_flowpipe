# Double Pendulum more: bounded validated-witness attempt

This is an isolated **method diagnostic**, outside the four flowpipe cells. It did not modify or restart any prior run. It attempted to turn the saved strict-interior numerical candidate `(binary64 1.299)^4` into a closed-loop violation certificate for the fixed official more-robust ONNX and the official continuous plant. The result is **incomplete**: the first interval enclosure refusal occurred at `t=0.1954`, before the numerical candidate's `θ̇₁=-1.5` crossing near `t=0.324865`. It supplies **no rigorous counterexample**, no complete-horizon result, and no four-method timing sample.

## Reproducible inputs and calculation

- [export_weights.py](export_weights.py) read the already fixed server ONNX at `.../runs/archcomp26_20261001/native_dp_more_prep_001/controller_double_pendulum_more_robust.onnx` without a digest. The model graph was `MatMul→Add→ReLU→MatMul→Add→ReLU→MatMul→Add`, with float32 layers `4→25→25→2`. Its float32 initializers are stored as [weights_float32.json](weights_float32.json). JSON numbers were emitted from float64 values that exactly represent the original float32 values; `float.as_integer_ratio()` in the verifier recovers those binary values exactly.
- [validated_point.py](validated_point.py) uses integer interval endpoints in units of `10^-35`. Its addition, multiplication and division round outward by integer floor/ceiling. Sine and cosine endpoints use 30-term interval Taylor sums plus a proven `<10^-35` Lagrange remainder on `[-1.5,1.5]`; sine monotonicity and cosine evenness/monotonicity on that domain turn endpoint values into interval bounds. Its NN interval calculation includes input conversion, float32 product/reduction and Add round-to-nearest error for arbitrary reduction order with standard 24-bit significand, but assumes no reduced-mantissa backend such as TF32. Thus it defines one explicit arithmetic contract and does not certify every possible ONNX backend.
- Each `0.02 s` held-control period used 200 substeps of `h=0.0001 s`. Each ODE substep first checked a Picard self-enclosing time tube. Its endpoint enclosure then used interval Taylor order two, `X+h f(X,U)+h²/2 J(Y,U)f(Y,U)`, with the Jacobian generated by interval automatic differentiation. The control is evaluated once from the period-start state interval and held for the period. These are enclosure operations, not a restarted benchmark method.

[RESULT.json](RESULT.json) preserves nine complete period-end state/control enclosures and the first refusal. **1,954** substeps were validated through `t=0.1954`; the next Picard tube did not self-enclose within the verifier's ten widening iterations. At `t=0.18`, the accepted `θ̇₁` endpoint interval was `[-0.8696329782103307,-0.2174282921088542]`, already width about `0.6522`; the corresponding NN `T1` interval was about `[-4.23318,-2.69625]`. All nine saved numerical replay controls lay inside the corresponding NN interval bounds, a consistency check only. The widening is driven by repeated box wrapping and interval NN uncertainty; at this point it cannot determine whether the unique trajectory later crosses the safety boundary. The saved numerical candidate's `t=0.36` value `θ̇₁≈-1.60717` remains only a candidate.

The precise blocker is a *tight, validated closed-loop enclosure from `t=0.1954` through a violating time* under a frozen NN arithmetic contract. This simple box/Picard/Taylor-2 method loses state correlation and its interval NN bounds expand across control updates. A Taylor-model or other correlation-preserving validated solver, and an independently fixed interpretation of ONNX backend arithmetic, would be needed before claiming an actual counterexample. No extra tuning run followed the first refusal.
