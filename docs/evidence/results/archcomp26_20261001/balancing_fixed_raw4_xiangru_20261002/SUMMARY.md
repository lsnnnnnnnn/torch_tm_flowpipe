# Balancing fixed-repository raw4: Xiangru attempt

This is the separately named `balancing-fixed-repo-raw4` profile: one complete physical initial box, fixed four-input CartPole ONNX with raw input order `(x1,x2,x3,x4)`, one held force per `0.02 s` period, and a planned 500 periods / 2000 ODE substeps at `0.005 s`, order 6. The fixed-repository property is `x1,x3,x4∈[-0.001,0.001]` for `8<t≤10 s`; the full-run checker includes `t=8` using continuity and the closed target box. This is **not** the paper's five-feature controller. Server source was staged in a new `balancing_fixed_raw4_xiangru_v1` directory; existing Huan/P3 runs were not restarted or overwritten. No content digest was computed.

The independent scanner found a separate saved-range issue: strict endpoint containment fails in the saved tube at one bound in the one-period run and 189 bounds in the full configuration. The first full-run case is substep 4, physical state `x3` lower bound: tube `-0.10234991023349767`, endpoint `-0.10234991023349771` (difference `4.163336342344337e-17`, three ULP at the tube bound). The largest recorded absolute difference is `2.4868995751603507e-14` (largest 15 ULP). These observations keep **solver acceptance** separate from a strict independent certificate for the saved tube. The cause has not been established. The same 189 count and maximum absolute difference appear in the previously saved Huan full-run ledger on a direct read, but no shared implementation cause is asserted.

Direct comparison of the two saved ledgers over their common 98 accepted substeps found all 784 Xiangru tube bounds and all 784 endpoint bounds equal to the existing Huan values. This is an observation about saved outputs, not an implementation identity or independent proof.

The original attempt directories, `START.json`, `config.yaml`, `ranges.jsonl`, property ledger, metrics, `RESULT.json`, console logs, and [server source snapshot](balancing_fixed_raw4_xiangru_v1/) are preserved under this directory.
