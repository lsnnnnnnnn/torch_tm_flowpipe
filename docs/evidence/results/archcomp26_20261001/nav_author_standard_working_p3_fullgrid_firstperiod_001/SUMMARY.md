# NAV standard working-P3: all 640 initial boxes, first control period

This is one new, isolated diagnostic on the named fixed-official NAV point-controller and author-execution profile. It covers all `40×16=640` source initial boxes, but only `t∈[0,0.2]` of the 6-second horizon. The historical `engine_linear_leaf_v2` full run was not repeated. The original run remains at `/srv/local/shengenli/flowstar_acceleration_20260921T153643Z/runs/archcomp26_20261001/nav_author_standard_working_p3_fullgrid_firstperiod_001`.

The run used the fixed 2026 `nn-nav-point.onnx`, source box ledger, `[x,y,speed,heading]` input and `[speed_rate,heading_rate]` output, `x'=speed cos(heading), y'=speed sin(heading), speed'=u1, heading'=u2`, one held-control period of 0.2 s, 20 ODE steps of 0.01 s, working P3 / validation order 4, strict endpoint and injection, box same-slope CROWN and `rpc-float32` transport. Physical GPU1, CPU6–9, an 11 GiB GPU allocation cap, and a 600-second process timeout were used. The controller is evaluated in process; no RPC listener was started.

The original [RESULT](RESULT.json) reports `completed_short_prefix`, process exit 0, 20/20 substeps and 12,800/12,800 accepted box-substeps, 5.243638020008802 s outer wall, 178,549,248 bytes peak GPU allocated and 530,579,456 bytes peak reserved. The T=0.2 endpoint unions are x `[2.8801980823379663,3.0801988228058668]` and y `[2.897353100520727,3.0973491843607532]`. These are one-run measurements, not a speed ranking.

The [independent scan](INDEPENDENT_SAVED_RANGE_AUDIT.json) reread every accepted interval in the raw [observations](observations.jsonl), using the copied exact [initial-box ledger](initial_boxes.json). It found all 640 boxes at each of 20 steps, finite and ordered bounds, endpoint inside each matching tube, all first-step tubes containing their source initial boxes, and no saved x/y tube intersecting the closed obstacle `[1,2]²`; all anomaly counts are zero. The scan establishes saved numerical coverage, not an independent floating-point NNCS proof.
