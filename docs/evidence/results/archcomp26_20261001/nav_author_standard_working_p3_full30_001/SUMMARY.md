# NAV standard working-P3: 640 boxes through T=6

This new, isolated run uses the named fixed-2026-official NAV point ONNX plus the controller author's executable state order `[x,y,speed,heading] → [speed_rate,heading_rate]`. It did not restart the historical `engine_linear_leaf_v2` run or either prior one-period gate. The plant is `x'=speed cos(heading), y'=speed sin(heading), speed'=u1, heading'=u2`; held control is sampled every 0.2 s for 30 periods, with 600 ODE steps of 0.01 s. The original 40×16 source ledger supplies all 640 boxes. The all-time closed obstacle is `[1,2]²` in x/y, and the terminal closed target at T=6 is `[-0.5,0.5]²`.

The saved working P3 uses order 3 with validation order 4, strict endpoint and two-control injection, box same-slope CROWN and `rpc-float32` transport. The run used physical GPU1, CPU6–9, an 11 GiB GPU allocation cap, and a 3,600 s supervisor timeout; CROWN ran in process without an RPC port. The original [START](START.json), [RESULT](RESULT.json), [supervisor receipt](SUPERVISOR_RESULT.json), [configuration](config.yaml), [initial boxes](initial_boxes.json), [600-step observation log](observations.jsonl), [metrics](metrics.json), and [deployed source and console](source_snapshot/) are mirrored here.

The original RESULT is `completed`, process exit 0, no timeout, **600/600** substeps and **384,000/384,000** accepted box-substeps. The author checker printed `VERIFIED`; this label follows its whole-tube obstacle and terminal post-handoff target checks. The outer one-run wall was **28.999885 s** (driver internal 25.865370 s). Peak GPU allocation was 1,164,581,376 bytes; peak reservation was 2,709,520,384 bytes. This single measurement is not a stable four-method speed ranking.
