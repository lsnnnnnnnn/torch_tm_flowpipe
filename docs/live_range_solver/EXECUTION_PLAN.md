# 在线范围服务预注册

目标文件：`/srv/local/shengenli/codex/goal_vdp_terminal.md`（2026-09-09）。
父提交：`b60a608a5d2b431aee0fe49a6cb7c3e18bcfdb3a`。

使用原 prepared replay、packed boundary 和已校正的范围请求算术。旧公开默认
不变。一个任务至多一个未消费请求；工作线程只提交真实当前输入，单独服务线程
按完整语义键分组。接受边界以整个状态原子替换，取消、失败或旧 epoch 不得提交。

两个候选固定为最大组 32、最长就绪等待 2 ms / 20 ms。达到组上限、全部存活
任务等待、或最老请求超过上限时派发；不同键之间按最老就绪顺序服务。只用两系统
B8 两步短前缀的 Q/G 总墙钟开销选择策略，随后冻结，不根据正式结果再选。

所有主要路线固定 CPU affinity `[2]`，Torch intra/inter-op = 1，GPU = 0。
L 是旧最快逐任务路径；S 是严格 CPU 请求接口串行求解；Q/G 是相同在线调度架构
的 CPU/CUDA 后端；S_gpu 只用于同 CUDA 后端的状态一致性。

依次运行 B1/B2 两步，B8 二十步，B32 二十步；两系统 task 0/31 连续 120 步；
历史 VDP99/100/101、Brusselator999/1000/1001 标记 RESUMED_LOCAL_WINDOW；
另跑原未分区 B1 二十步。B8 拆分/顺序/延迟验证用两步固定前缀。
独立 Fraction 核验完整 B32 首两步，120 步中的 1、2、60、100、119、120 步，
新结构、外供表、纠正类型和故障/取消/重试边界前后成功请求。

正式 B8/B32 的 S/Q/G 二十步各三组，顺序为 S/Q/G、G/Q/S、Q/S/G。
B1 三次短跑（两步）；L 同任务有限实跑一次。诊断与正式计时分开。
从初始状态建立到任务终止计时，包含启动、正常检查、全部请求、失败与清理。
模块编译/加载及原语自检的冷启动另记；预热服务重复使用同一进程中已编译模块。

仅当两系统 B32 的 min(S,Q)/G 配对三组至少两组 > 1、中位数 >= 1.10，且
正确性、完整工作量、资源一致性通过时，称实用在线流程提速。1.00–1.10
方向一致为小幅改善；只胜 Q 不胜 S 为调度成本吞噬收益。对 L 单列。
不以速度失败为理由改数学参数、增加算子或改历史传播。

交付包含服务、实际连续求解驱动、生命周期/故障测试、独立证据验证器、八类
重新计算外层摘要后的篡改测试、原始压缩记录、中文报告、逐项目标审计。
先冻结科学源码再正式计时，最后推送自己的分支，在独立副本有界复跑与核 SHA。
