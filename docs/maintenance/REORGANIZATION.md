# Review-branch reorganization

The independent branch starts from fixed parent `8ca0bb034f597db3e16bce83ad974422a9b74bba`. The dirty older `/srv/local/shengenli/torch_tm_flowpipe` worktree and main were not changed. A July `repository-consolidation-v1` remote branch was inspected but predates the September resident/packet/endpoint work, so it was not merged. No history was rewritten and no old scientific package was modified to manufacture a current result.

The one-time [asset disposition inventory](asset_disposition.csv) groups 11,929 parent tracked files into 452 source/experiment/document/run groups, recording path, type mix, size, direct code/test references, disposition and fixed recovery commit. It treats basename references assembled by `ROOT / "outputs" / "name"` as dependencies, not just contiguous string matches. The main selected endpoint, packet, Flow*, resident, C3/C4, CPU-pair and numerical-repair raw packages remain at their original tracked paths. In particular, [the matched contracts](../../artifacts/runs/xiangru_adoption_20260907T032448Z/MATCHED_CONTRACTS.json), the two older helper modules imported by `experiments/endpoint_roundoff_repair/frozen.py`, the packet route's partition plan, and historical verifier fixtures are still support dependencies; moving them merely for directory appearance would break current reproduction.

Four groups totaling 1,160 tracked files and 255,712,130 bytes were removed only from this current branch tree: two replaced July repository-audit groups and two older VDP trace/matrix output groups with no active direct reader. [The recovery index](../../archive/index.csv) gives each exact old path, purpose, parent commit and command. The G2 historical document can still be read at its fixed revision; its diagnostic matrix source is explicitly recoverable instead of being relabeled as a current experiment. Negative results were not selected by whether they look favorable. The 16,000-row GPU-vs-reference historical comparison and its complete source models remain, as do the local-fast/online-small GPU results and legacy early-stop evidence.

This is a current-tree and entrypoint cleanup, not a promise to shrink all Git history. Some large historical `outputs/`, `evidence/` and `artifacts/` branches remain because active tests or dynamic legacy scripts read them. They are support, not alternative front-page “final” reports. The new one registry, one review CLI, generated experiment map and clear README define the supported reading/reproduction route; historical scripts can be replayed at fixed commits without being misadvertised as current backends.

Before removal, `pytest --collect-only -q` found 1,285 test IDs. Immediately after the four-group removal, the same 1,285 IDs remained with zero lost or added. The complete checkpoint test result, skip reasons, clean-clone install/replot receipt and fresh-run checks are in [the validation record](VALIDATION.md). The parent and reorganized worktree's two-system, two-step same-contract trajectory matched exactly for config, accept/reject, endpoint/tube x/y hex bounds, symbolic queue SHA and accepted-state SHA; [the receipt](short_trajectory_equivalence.json) keeps those exact values. Core numerical and established runner modules were not rewritten. Wheel inspection found all three required `.cu` sources while CPU smoke imported and ran without compilation.

If a later maintainer wishes to move more old support, first inspect literal and constructed imports, subprocess paths, archived manifests, and collected tests; add exact source/restore mapping before changing the tree. Old raw-run identities and their hashes are immutable. A new run or changed numerical source needs its own registry version and bounded revalidation; a document change alone does not turn a historical run into a fresh one.
